# 摄影系列图片排版

在工作室展开系列，进入“图片排版”，切换“自定义排版”。初始分组沿用当前画册，调整不会立即影响网站；点击“保存排版”或“保存系列”后生效。

系列顶部的“保存系列”会一次保存基本信息、权限、系列文字、图片排版和顺序，以及所有照片的替代文字、注释、地点和日期。全部校验通过后才在一个事务内提交，失败保留输入。文字区、排版区和单张照片旁的保存按钮仍可单独使用。

系列文字、图片排版、图片与标注默认分别折叠，标题显示内容数量和未保存状态。可独立展开，或展开／折叠全部。本次工作室访问保留各系列的展开状态与编辑草稿，刷新后默认折叠；章节、排版和照片编辑链接自动展开目标区域。上传入口位于图片与标注区域顶部。

- 单图：通栏、居中窄幅。双图：原比例等高、左宽右窄、左窄右宽。三图：原比例等高、左大右两小、左两小右大。四图：两行两列。
- 拖动“⠿”手柄移动照片或整组。拖到组间区域可独立成组；所有移动、合并和拆分也有按钮。
- 每组选择留白或无缝。默认保留整张照片；固定画框可切换“填满”，拖动取景或使用水平、垂直滑杆。原比例模板保持原构图。
- 每组可设置正文版心的 25%～100% 宽度，居中展示图片与注释，提供 100%、85%、70%、55% 快捷按钮、滑杆和整数输入。“模板默认”保留原窄幅最大 640px 的设置；主动选择百分比后覆盖模板宽度。手机低于 768px 始终逐张全宽展示。
- 移动组和切换模板保留宽度；拆分继承原组宽度，合并采用前组宽度；照片移入已有组采用目标组宽度，新上传照片独立组使用模板默认。一次宽度滑杆拖动对应一次撤销。
- 实时预览直接使用未保存内容。手机始终逐张完整展示；点击放大也始终看完整照片。
- 章节起点随照片移动，跨章节的组合会拆开；不允许跨章节合组。支持撤销、重做。恢复自动排版保留当前照片顺序，需要保存才生效。
- 新照片追加为独立组。删除照片前需保存文字与排版；删除章节起点仍需明确移动或删除章节。

## 保存与兼容

`Series.layout` 为可选值，`null` 表示自动排版。自定义结构：

```json
{
  "version": 1,
  "groups": [{
    "id": "stable-group-id",
    "template": "pair",
    "gap": "space",
    "widthPercent": 85,
    "items": [
      { "photoId": "photo-a", "fit": "contain", "x": 50, "y": 50 },
      { "photoId": "photo-b", "fit": "cover", "x": 25, "y": 75 }
    ]
  }]
}
```

沿用 `POST /api/studio` 的 `action: "upsert", entity: "series"`。携带布局时，系列记录必须同时携带当前 `version` 和 `photoOrder: [{id, version}]`，照片清单必须完整且与分组顺序一致。服务端在同一事务内保存系列及照片顺序，只更新照片的顺序、版本和时间，不写入照片正文或文件字段。冲突返回 409，格式错误返回 400；失败保留工作室输入。未携带布局的旧保存请求保留现有布局。

“保存系列”使用 `action: "save-series", entity: "series"`，记录同时包含完整的 `photos: [{id, seriesId, version, alt, caption, location, takenAt}]`。与布局和顺序同一事务保存，仅变动的照片更新一次版本，不修改图片文件、尺寸或所属系列。响应包含保存后的系列信息、规范化照片文字和最新顺序版本；前端只确认提交时的快照，保存期间继续输入的内容保持未保存。

`draftPhotoOrder` 仅供工作室未保存预览，数据库不保存该字段。空布局旧系列无需转换，原文件保持不变。私藏系列的布局和照片引用不下发给访客。

布局沿用 `0005_series_layout.sql` 中的 `layout_json`。组宽字段 `widthPercent` 可选，仅接受 25～100 的整数，缺省为模板默认，本次无需数据库迁移。

同步结构版本为 7，本地与线上需同时升级。版本 3、4、5 的旧备份缺少布局时保留现有布局；携带旧布局时为稳定组 ID 和照片成员均匹配的组保留现有宽度。不匹配时明确报告冲突，不自动丢弃宽度或布局。版本 6 备份恢复其完整布局，包括主动恢复模板默认的设置。关联系列与照片的同步冲突整组处理，并拒绝覆盖冲突发生后的新编辑。
